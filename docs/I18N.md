# Idiomas do painel (i18n)

O painel do ZapHub está em **português do Brasil** (padrão) e **inglês**. As traduções usam o [`next-intl`](https://next-intl.dev) no modo por cookie: os endereços não mudam (não há `/en/...`) e a API REST não é afetada.

## Idiomas disponíveis

| Código | Idioma |
| :--- | :--- |
| `pt-BR` | Português (Brasil): padrão e idioma de reserva |
| `en` | English |

## Como o idioma é escolhido

Em cada requisição, o servidor usa o primeiro que encontrar:

1. o cookie **`NEXT_LOCALE`**, gravado pelo seletor de idioma (barra superior, menu do celular, telas de login e cadastro);
2. a variável **`DEFAULT_LANGUAGE`** do `.env`;
3. **português (`pt-BR`)**.

A comparação é tolerante: `pt-br`, `PT-BR` e `pt` viram `pt-BR`; `en-US` vira `en`. Valores desconhecidos são ignorados.

O fuso das datas exibidas vem do `TZ` do `.env` (padrão `America/Sao_Paulo`).

## Onde ficam os arquivos

```
src/i18n/
├── config.ts            # idiomas suportados, cookie, regra de escolha
├── request.ts           # configuração do next-intl (lê o cookie e carrega as mensagens)
├── actions.ts           # Server Action usada pelo seletor de idioma
├── global.d.ts          # tipagem das chaves (com base no en.json)
├── messages/
│   ├── pt-BR.json
│   └── en.json
└── __tests__/           # rodados pelo npm test
src/components/language-switcher.tsx
```

## Usando traduções nos componentes

```tsx
import { useTranslations } from "next-intl";

export function Exemplo({ count }: { count: number }) {
    const t = useTranslations("notifications");
    return <p>{t("unreadSummary", { count })}</p>;
}
```

- Em componentes de servidor assíncronos, use `getTranslations` de `next-intl/server`.
- As mensagens usam a [sintaxe ICU](https://next-intl.dev/docs/usage/messages): `{name}`, `{count, plural, one {...} other {...}}` e trechos com tags, como `<terms>...</terms>`, com `t.rich()`.
- Datas e números: use `useFormatter()` para seguir o idioma ativo.

As chaves são **verificadas pelo TypeScript** com base no `en.json`: um erro de digitação como `t("seeAlll")` falha no `tsc --noEmit` e no `npm run build`.

## Traduzindo uma parte nova da interface

1. Adicione as chaves novas em **`pt-BR.json` e `en.json`**, agrupadas por tela (ex.: `"broadcast": { ... }`). Os dois arquivos precisam ter exatamente as mesmas chaves.
2. Troque os textos fixos por `t("...")`.
3. Rode `npm test` e `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json`.

## Adicionando um idioma

1. Copie `src/i18n/messages/en.json` para `src/i18n/messages/<código>.json` (ex.: `es.json`) e traduza os valores. Não mude as chaves, os `{placeholders}` nem as `<tags>`.
2. Registre o código em `locales` e o nome nativo em `localeNames`, em `src/i18n/config.ts`.
3. Rode `npm test`.

## Testes

```bash
npm test
```

Eles conferem que:

- cada idioma em `config.ts` tem um arquivo de mensagens, e vice-versa;
- **todos os arquivos têm exatamente as mesmas chaves** que o `en.json`, sem valores vazios;
- os placeholders e as tags batem com o `en.json`;
- toda mensagem é montada sem erro de ICU;
- os plurais e a ordem de escolha (cookie, `DEFAULT_LANGUAGE`, reserva em português) funcionam.
